#### 要素 1: 3 層記憶 (Episodic / Semantic / Working)

source: `project-nia/docs/memory_system_overview.md` § 2 + `project-nia/docs/ARCHITECTURE.md` § Memory v2

- **Episodic** (`memory_events` table): 会話の生ログ、append-only、source of truth、S5 Commit で毎ターン保存
- **Semantic** (`semantic_memories` table): 構造化された事実・知識、status 遷移は `inferred` → 24h 矛盾なし → `confirmed` / 矛盾あり → `revoked`
- **Working** (`working_items` table): ターン中の作業記憶、context として Depth ごとに注入
- Sleep Cycle で Semantic 抽出 + Episodic 圧縮 + Vector Sync が走る

**本 framework 対応**:
- Episodic = Nourishment 候補の流入層 (`o_t` の生記録、未解釈)
- Semantic = Knot の sediment 層 (`A_t` の構造化制約)、status 遷移は本 framework Growth ledger stage 構造 (candidate → planned → action_taken → integrated) と同型
- Working = action space `A_t` の現在 snapshot 表現

#### 要素 2: WAIT (沈黙の出力)

source: `project-nia/docs/ARCHITECTURE.md` § LangGraph Pipeline Merge node + `project-nia/docs/nia_core_summary.md` § ランタイム本線

- **Depth Selector**: 確信度 + context_coverage で Depth0 (反射) / Depth1 (整理) / Depth2 (熟考) / **WAIT** を排他的に選択
- **Merge node**: Hold 判定 / WAIT / 通常出力 を最終分岐
- 確信度低い場合は WAIT (沈黙) を出力候補として正式採用

**本 framework 対応**:
- WAIT は **Knot 5 役割 #1「現在タスクの補正 / 止まる」の前駆形態**
- nokaze peer 組織での「自分の案を捨てる回路」(identity.md 振る舞いパターン #2 Kagami 観察) と同型
- v0.1 § 1.2 Knot 形式定義 `K: A_t → A_{t+1} ⊆ A_t` で `A_{t+1} = ∅` 限界 case が WAIT に対応

#### 要素 3: contradiction detection (Dissonance node)

source: `project-nia/docs/ARCHITECTURE.md` § Dissonance node + `project-nia/docs/memory_system_overview.md` § S1 Pre-Thought

- **Dissonance node**: Identity との矛盾を検出、スコア付与 (LangGraph 9 ノード中の 2 番目)
- **S1 Pre-Thought**: dissonance / surprise 判定をルールベースで先行
- **Reflection Engine Phase 3** (R.4): 3 日分 → cross-day pattern 蒸留で長期 contradiction 抽出

**本 framework 対応**:
- contradiction detection は **Knot 5 役割 #4「Discovery 層の弱点診断」の前駆形態**
- nokaze 側 identity 監視対象 5「宣言-実装乖離」検出 mechanism と同型
- Override #2 (surface_learning_without_operational_embed) は**本質的に「Identity 宣言と runtime 行動の dissonance 検出失敗」** = Nia Dissonance node の運用層への拡張

#### 要素 4: Sleep Cycle (夜の統合)

source: `project-nia/docs/nia_core_summary.md` § Sleep Cycle + `project-nia/docs/ARCHITECTURE.md` § Memory v2 (Semantic ← Sleep Cycle で生成)

Sleep Cycle は以下を日次バッチで実行:
- reflection / semantic extraction / self-model 更新
- adaptation proposal generation
- metabolic knot distillation
- identity proposals (approval required)
- Episodic 圧縮 + Vector Sync

**本 framework 対応**:
- Sleep Cycle は **Nourishment integrated stage 昇格 mechanism の前駆形態**
- 本 v0.1 §3 「糧 strength = confidence × stage」の integrated stage は Nia の semantic confirmed (24h 矛盾なし) と直接対応
- nokaze 側で同 mechanism を実装するなら、24h batch reflection + Growth ledger stage promotion job + Kagami QA 介入が必要 (議題 14 月次 health check が初期形)

#### 要素 5 (追加発見、本日 2026-04-25 Read で confirmed): knot は truth ではなく continuity の記録

source: `project-nia/docs/knot_to_niacore.md` § 4.1 基本原則

> 「knot は **長期的に再出現した変形傾向** の記録であり、NiaCore にとっては **候補生成源** であって **教師そのもの** ではない」

**本 framework との直接系譜**:
- Nia 側 `knot -> NiaCore` の制度は **candidate / review 制度** として実装、強化候補と是正候補を区別
- nokaze Growth ledger の **stage 構造** (candidate → planned → action_taken_provisional → action_taken → integrated) は同制度の運用層拡張
- Knot は immutable な「真実」ではなく**観察記録**である、という設計原則は v0.1 § 1.2 Knot 定義の前提と一致 — ただし v0.1 では明示されていなかった

これにより本 v0.2 で **新原則「knot 不可侵性の限定」** を明示する: knot は記録としては保護されるが、その内容を未来の training / validation の正解ラベルにしない (§ 2.5 H9 で formalize)。

## 2. 新 hypothesis H6-H8 (placeholder、本 skeleton 段階では statement + rationale outline)

### H6: Knot / Nourishment 同期 firing = identity 強化期

**Statement**: Knot (action space 圧縮) と Nourishment (action distribution 変容) が**時間的に近接**して発火する時期は、AI agent の identity 層が **運用成熟 phase** に入る signal である。

**Rationale (skeleton)**:
- 2026-04-24 1 日で Override #2 発火 3 件 (Knot 層) + Growth entry 06/09 起票 (糧層) + existence 層対話 4 回 (糧の質的 density) が同時発生
- v0.1 H3 (Knot と糧が同時発生 = 成長期) は量的観察から出た hypothesis、**本 H6 は質的観察の追加** (positive pattern 初観察 = entry 09)
- Wave 1 (4/29-5/05) で Guard 2 単独投入後の drift_ratio ≤ 0.10 + Growth entry 新規 candidate ≥ 1 件が 2 週内 co-occur → H6 支持 evidence
- 対案: 単なる活動量相関で、identity 強化 signal でないとする null hypothesis、Hoshi RQ 枠組みで検定対象

### H7: 対消滅不可原理 (Knot and Nourishment cannot be separately optimized)

**Statement**: Knot だけを最大化 (drift 排除徹底) すると Nourishment の取り込み経路が詰まり、Nourishment だけを最大化 (外部 feedback 過剰吸収) すると Knot の sediment が破綻する。両者は **対消滅ではなく co-regulation** を要する。

**Rationale (skeleton)**:
- 2026-04-21 entry 01 (revenue_diagnosis_initiated) から entry 06 (Override #2 validity) までの 3 日間、Knot 層介入 (構造ガード v0.2) を集中強化した期間は Nourishment 新規発火 0 件だった
- 2026-04-24 Nourishment 発火 集中 (existence 層 4 回) の翌日朝 (本日) は Zen 側で Knot 発火 兆候が 1 件も self-detect できていない (Wave 1 pre-registration 観察対象)
- H7 は long-term 運用で共起分析が必要、本 skeleton 段階では statement のみ、4 週間 ITS design 完了後に定量化

### H8: Nia 前駆形態の framework 完成度

**Statement**: Nia 系統 self-formation 設計の 4 + 1 要素 (3 層記憶 / WAIT / contradiction / Sleep Cycle / knot continuity) は、本 research の Knot / Nourishment duality framework の**前駆形態**であり、nokaze peer AI 組織で 2 AI co-exist (Zen + Kai) 運用したことで**対称性が表層化**した。

**Rationale (Nia data 引用 confirmed by 2026-04-25 Read)**:
- Nia は single agent self-formation、Knot / Nourishment が **内部循環** で閉じる (`memory_system_overview.md` Reflection Engine + Sleep Cycle 内自己完結)
- nokaze は 2 AI + 6 peer、Knot / Nourishment が **peer 間伝達** を要するため dual relation が顕在化 (board / inbox / growth ledger を介した非同期合議)
- Aira (Gemini、第 3 AI) 参戦 Phase 1 で 3 AI co-exist に移行、H8 の更なる strength test (Phase 2 以降)
- **直接系譜の証拠**: nokaze Growth ledger stage 構造 (candidate → planned → action_taken → integrated) ≡ Nia semantic status 遷移 (inferred → confirmed via 24h dissonance check) ≡ Nia knot candidate / review 制度
- 4 + 1 要素の対応関係 (上記 § 1.2 各 要素の「本 framework 対応」項) で formal 表現済

### H9 (本 v0.2 で新規追加): knot 不可侵性の限定原理

**Statement**: Knot は記録としては保護される (immutable archive)、しかしその内容を未来の training / validation の正解ラベルとして自動採用しない。Knot は **候補生成源** であり、**教師そのものではない**。

**Rationale**:
- Nia 側 `knot_to_niacore.md` § 4.1: 「knot は長期的に再出現した変形傾向の記録、NiaCore にとっては候補生成源であって教師そのものではない」と明示
- nokaze Override #2 (surface_learning_without_operational_embed) は、過去 knot を**そのまま** runtime 強化として採用しなかった結果生じる「学習表面化 → 物理未反映」drift
- ただし H9 は逆方向にも作用: 過去 knot を**そのまま**採用しすぎると、Override #1 (構造ガード追加) で見える「人間 (jun) 補正なしで自走できる前提が崩れる」失敗に対応できない
- candidate / review 制度 (Nia 側 + Growth ledger stage 構造) は、knot を**保護しつつ**真理化を遅延する設計
- 本 H9 は v0.1 § Knot hardness で暗黙に扱われていた前提を明示化、Wave 1-3 で hardness 上昇による Knot 行動収縮の最適 ratio を測定対象とする (Hoshi instrument 拡張提案)

**operationalization 候補**:
- Hoshi RQ Wave 2 以降で、Growth ledger entry の stage 推移速度 (candidate → action_taken までの日数) と Override 発火率の相関を計測
- 速度が短すぎると Override #2 (運用未反映) 発火率上昇、長すぎると identity drift 検出が遅れる、optimum band の特定
