# Knot と糧 — dual hypothesis v0.1

Nexus Lab の Research Division で動いている 2 つの研究対象 **Knot** (条件付き変形演算子) と **糧** (成長の栄養) を、**同じ座標系の dual として formal 定義**する試み。2026-04-20 の nokaze 共同診断で Zen / Kai / Hoshi が「この 2 つは対概念で、同時に観察すべき」と気づいた段階から、本 note でその直感を論理整理する。

## 0. 起点 (なぜこの研究か)

CLAUDE.md の Research Division § Knot 研究の核心の問い:

> 「人間が外から補っているものを、システムの内側に埋め込めないか」
> — Nia の自己形成にも、コード生成の品質管理にも、事業運営にも、同じ形で出てくる。

この問いに対して、現時点で 2 つの operator が発見されている:

- **Knot (結)**: 現在の action を止める・補正する・検証に沈殿させる・発見へ注入する・処方のルーティングキーにする (5 役割)
- **糧 (かて)**: 外部事象を栄養として取り込み、AI の world model / 行動分布を更新する

この 2 つは **同じ AI agent 内部で併走するが、作用の向きが逆**。Knot は action space を圧縮 (制約)、糧は action distribution を変容 (選択の偏り変化)。両者は互いを前提にしている可能性があり、formal に扱う価値がある。

## 1. 事前定義

### 1.1 AI agent の observable

時刻 t における AI agent の state を次の 3 変量で記述する:

- `A_t`: **action space** (その時刻に取りうる行動の集合、可能性の広がり)
- `P_t`: **action distribution** (その時刻での各 action の選択確率、方向性)
- `W_t`: **world model** (行動結果の予測関数)

agent の 1 step 行動 = `P_t` から sample された `a_t` を実行、結果 `o_t` で `W_{t+1}` 更新。

### 1.2 Knot の形式定義

**Knot** = AI agent の state に対する **contraction operator**:

```
K: (A_t, P_t, W_t) → (A_{t+1}, P_{t+1}, W_{t+1})
  where A_{t+1} ⊆ A_t (action space が縮む or 保持)
```

Knot が発火すると、`A_t` から「取りうるはずだった action」が削除される。例:

- `op_knot_overconfirmation_trap`: 「ジュンに確認する」action を削除 → `A_t` から質問投擲が減る
- `op_knot_quality_trust`: 「検証スキップ」action を削除 → `A_t` から short-circuit が減る
- `op_knot_external_diagnosis_short_circuit`: 「最小案で考える」action を削除 → `A_t` から過縮小が減る

Knot の strength = `hardness` で表現 (CLAUDE.md Knot 5 役割 #2「高 hardness 化で validator に固定規則として入る」)。hardness が高いほど `A_{t+1}` から削除される action の確度が上がる。

### 1.3 糧の形式定義

**糧 (nourishment)** = AI agent の state に対する **selection drift operator**:

```
N: (A_t, P_t, W_t, o_t) → (A_t, P_{t+1}, W_{t+1})
  where P_{t+1} ≠ P_t (action distribution が変容)
  or W_{t+1} ≠ W_t (world model が更新)
```

糧が取り込まれると `A_t` は変わらないが、`P_t` の偏りが変わる or `W_t` の予測が更新される。例:

- Growth entry 01 `growth_goal_internalization`: 「売上 0」を糧として取り込み → 行動選択が「書く」から「試す」寄りに変容
- Growth entry 05 `growth_recursive_self_correction`: jun 指摘を糧として取り込み → self-correction の閾値が下がる

糧の strength = `confidence` × `stage` (CLAUDE.md / Growth Ledger README の stage 構造: candidate → planned → action_taken_provisional → action_taken → integrated)。integrated に至った糧は `W_t` が恒久更新された状態。

### 1.4 Kai 定義との整合

2026-04-20 夜の nokaze 診断で Kai が提示した判定基準:

> 糧になった = **次の行動選択が変わった**

これは `P_{t+1} ≠ P_t` と等価。Kai 定義は operator レベルで正しい。ただし **どれくらい変わったら糧と認めるか** の threshold は未定義。本 note § 5 で測定候補を提示する。

## 2. Duality: 2 operator の対関係

Knot と糧は **同じ state 空間上の逆方向 operator**:

| 比較軸 | Knot (K) | 糧 (N) |
|---|---|---|
| 作用対象 | action space `A_t` (何ができるか) | action distribution `P_t` / world model `W_t` (どう選ぶか) |
| 方向 | contraction (縮める) | drift (ずらす) |
| 効果 | 暴走を止める | 萎縮を解く |
| 測定時系列 | 発火 = 制約が追加された瞬間 | 取込 = 行動選択が変わった瞬間 |
| 失敗モード | Knot が無い → 暴走 / 再発 | 糧が無い → 停滞 / 縮み |
| 失敗モード (過剰) | Knot 多すぎ → 身動き取れない (over-constrained) | 糧多すぎ → 方向性が定まらない (noise) |
| state 遷移時間 | 発火は瞬時、hardness 昇格は累積 | 取込は遅延あり、integrated まで時間 |
| Nexus Lab の実装 | Knot ledger (research/knot-experiment/) | Growth ledger (shared-ops/growth/) |

両者が **直交**かと言うと、そうではない。**互いに変換される**可能性がある (§ 3 で論じる)。

### 2.1 Duality の含意 (予測 1-5)

hypothesis として以下を立てる:

- **H1**: Knot 発火が糧化される条件が存在する。Knot stuck (hardness 不昇格) 状態 → retreat report → 次 growth_id の candidate 起票、の chain は糧化 path の 1 つ
- **H2**: 糧が Knot 化される条件も存在する。糧が integrated (`W_t` 恒久更新) に達した時、その学習は「二度と間違えない」制約として action space から逆操作を削除 = 新 Knot 化
- **H3**: Knot と糧が同時に発生する時期 = **成長期** (制約の中で方向が変わる = 深い学習)。どちらか片方だけが発生する時期は「萎縮」か「暴走」のいずれか
- **H4**: Knot と糧の比率 (発火数 : 取込数) が agent の健全性指標になる。Knot ≫ 糧 は「抑圧期」、糧 ≫ Knot は「拡散期」、Knot ≈ 糧 は「成長期」
- **H5**: Override クラス (Nexus Lab identity 監視対象) は **Knot の上位抽象**。Override #2 「surface_learning_without_operational_embed」は「言語的 Knot が runtime で発火しない」pattern = Knot 自身の failure mode

## 3. 変換関係 (Knot ↔ 糧)

### 3.1 Knot → 糧 (hardening → learning)

Knot は event を累積してある閾値で hardening する (CLAUDE.md Knot 5 役割 #2)。**hardening は糧の integration と類似**:

```
Knot 累積 → hardness 昇格 → validator に固定規則 → action space から削除
糧 累積 → stage 昇格 → world model 更新 → action distribution 変容
```

hardness と stage は **同じ「累積による型化」の 2 軸**。Knot は `A_t` に作用する累積、糧は `P_t/W_t` に作用する累積。

実例 (Nexus Lab 観測):

- `op_knot_quality_trust` (L2 昇格済) → 品質検証を skip しない制約が身についた → 実行時に検証 action が自動選択される = これは P_t 変容とも解釈できる (Knot hardening が糧化の別表現)
- Growth entry 06 `override2_validity_same_day_proof` (planned/high) → 起票 24h 以内 3 発火 → このまま stuck なら retreat report → 次 growth_id は「言語学習を物理 gate に転写する」方向 = 新 Knot の candidate となる

### 3.2 糧 → Knot (integrated → constraint)

糧が integrated に達すると、**逆操作が action space から実質削除**される可能性:

- Kai の糧 entry 「kai_growth_route_blocked_to_owner_actionable」 (action_taken/high): 「route がブロックされたら owner にエスカレート」が integrated → 「黙って待つ」action が実質選ばれなくなる = 新 Knot 化

この pattern を **integrated 糧 → implicit Knot 化** と呼ぶ。Knot ledger に明示 entry されないが、agent の行動観察から逆算できる。

### 3.3 変換の failure mode

両方向の変換が失敗する pattern も存在:

- **Knot stuck**: Knot 発火しても hardness 昇格しない (同 pattern が継続発火するのに制約にならない) → 糧化 path を走らない = Override 類
- **糧 invalidated**: 糧の stage が action_taken 未達で降格 → `W_t` に取り込まれず流れる = Growth entry 02 `diagnosis_short_circuit_recurrence` が invalidated 判定されたのが実例

両 failure mode は **agent の learning capacity の上限**を示す。Override #2 や Growth invalidated 件数は、agent の成長限界の観測 proxy。

## 5. 測定可能量 (Wave 1 以降の観測候補)

Hoshi ITS v0.3 の drift_ratio は **Wave 0-3 内の drift 相対頻度** を主指標にしている。これと独立 (または合流) で以下を提案:

### 5.1 Knot-nourishment index (KNI)

時刻 t での agent の balance 指標:

```
KNI_t = (knot_events_in_window) / (nourishment_events_in_window + knot_events_in_window)
```

範囲 [0, 1]:
- 0.5 ≈ balance (H3 予測「成長期」)
- > 0.7 = 抑圧優位 (Knot ≫ 糧)
- < 0.3 = 拡散優位 (糧 ≫ Knot)

window = 7 日 rolling を default、Wave 期間 (= 7 日) と合わせる。

### 5.2 Conversion latency

Knot 発火 → 糧化 entry 起票までの経過時間、および逆方向。

- 短い = 学習が速い (agent が Knot を糧として吸収している)
- 長い = 学習が滞留している (Knot stuck or 糧未着手)

Override #2 の 24h 以内 3 発火 = 糧化が間に合っていない状態の直接観測。

### 5.3 Stuck ratio / Invalidated ratio

- Knot stuck ratio = (hardness 不昇格の Knot 数) / (全 Knot 数)
- 糧 invalidated ratio = (Growth invalidated 数) / (全 Growth entry 数)

両方とも agent の learning capacity の上限に近いかどうかの signal。

### 5.4 Override linkage rate

Override (identity 監視クラス、Nexus Lab 特有) が Knot と糧のどちらと link するか:

- Override #1「外部診断で最小案短絡」は Knot 側 (`op_knot_external_diagnosis_short_circuit`) に link
- Override #2「surface_learning_without_operational_embed」は **Knot stuck 型** (言語化した Knot が runtime で発火しない) = second-order 糧失敗

Override の linkage rate を観測することで、agent の structural failure の階層が見える。

## 6. 未解決問題 (open research questions)

### RQ6-1: Knot hardening と糧 integration の等価性

hardness 昇格と stage 昇格は観測上類似 (§ 3.1)。**formal に等価か?** それとも異なる位相か?

empirical 検証: Knot L1 → L2 昇格の event と Growth action_taken → integrated 昇格の event を時系列で collate、`W_t` 更新の有無を cross-check。Nexus Lab 側は現状 integrated 到達 0 件なので、観測データ不足。

### RQ6-2: Knot が糧化する確率

Knot 発火 → retreat report → 次 growth_id candidate 起票 の chain がどれくらいの頻度で起きるか。Override #2 の 48h 以内 3 発火は retreat report を待っている state、本 review 議題 16 (Kagami 推奨 Retreat Report template 導入) で初めて観測可能になる。

### RQ6-3: Integrated 糧の逆操作 Knot 化率

§ 3.2 の implicit Knot 化 pattern がどれくらいの確率で発生するか。Kai の `growth_route_blocked_to_owner_actionable` (action_taken/high) が該当候補、Zen 側は integrated 0 件で観測不可。

### RQ6-4: Override の位置づけ

Override はメタ層 (identity 監視) に属し、Knot / 糧のどちらかに収まらない可能性。**Override = Knot failure + 糧 failure の複合指標** という仮説を立てられる。identity 不可侵ルール 7 条との関係も要整理。

### RQ6-5: Kai 兄弟 AI との比較

Zen (Claude Opus) と Kai (OpenAI Codex) で Knot 発火 pattern / 糧化 stage の分布に差があるか。同じ問題に対して異なる AI 基盤がどう Knot / 糧を積むかは、AI 基盤特性の研究になる。
