# 公開用語の対応表 (4 ヶ月初心者向け)

## これは何ですか

AI Operator Pack の中で出てくる、 ちょっと専門っぽい言葉を、 普段の言葉に翻訳した対応表です。

技術文書では英語の専門用語をそのまま使うことがありますが、 このパックでは **「何が起きているか」 を普通の日本語で説明** することを優先しています。

研究の現場で使われている言葉も、 商品としてあなたに届ける時には、 もう一度わかりやすい言葉に置き換えています。

## 用語の対応表

### 気づきと判断にかかわる言葉

| 専門の言葉 | 普段の言葉 | 何のことか |
|---|---|---|
| Knot (結び目) | **気づきの結び目** | AI が会話の中で 「ここ大事だな」 と気づいた瞬間の小さな印 |
| hardness (硬さ) | **気づきの硬さ** | その気づきがどれくらい確信されているか。 高い = ほぼ確定、 低い = まだ仮説 |
| Discovery (発見の層) | **発見** | 新しい気づきを生み出す働き。 あなたが話すたびに新しい発見が生まれる |
| Validator (確認役) | **確認役** | 過去に決めたルールを守る働き。 「これは前に決めたから」 と AI が判断する根拠 |
| Knot trace (結び目の足跡) | **気づきの足跡** | 過去の気づきがどう積み重なって今の判断になったかの記録 |
| Conversation Insights | **会話から気づきを拾う** | あなたとの会話の中から大事なことを Yuino が見つけて、 後で見返せるようにする機能 |
| Judgment Amplification | **判断を増幅する** | あなたの少ない判断を、 複数の AI に振り分けて、 もっと多くのことを進める仕組み |

### 安全と運用にかかわる言葉

| 専門の言葉 | 普段の言葉 | 何のことか |
|---|---|---|
| Approval Gate | **承認の関所** | 大事なことをやる前に、 あなたに 「これやっていい？」 と聞く仕組み |
| Audit Log | **作業の足跡** | AI がいつ何をしたかの記録。 後で全部確認できる |
| Fail Closed | **怪しい時は止まる** | 安全か分からない時、 AI は勝手に進まずに止まる仕組み |
| Reset / Forget | **全消し** | あなたが 「これまでの記憶を全部消したい」 を 1 click でできる仕組み |
| No silent state mutation | **勝手に変えない** | AI が裏で勝手に何かを変えない約束 |
| Mode visibility | **モードの表示** | 今あなたが 「内部運用 mode」 「商品 mode」 「公開 mode」 のどれにいるかが画面で分かる |
| Local-first | **手元で動く** | あなたのパソコンの中で動くこと。 大事な情報を外に送らないで済む |
| Permission model | **できることの境界** | AI が何を読めて、 何を書けて、 何を外に送れるかの境目 |

### 仕組みと運用にかかわる言葉

| 専門の言葉 | 普段の言葉 | 何のことか |
|---|---|---|
| closed loop | **ぐるぐる回る仕組み** | 観察 → 判断 → 実行 → 確認 → 復旧 → 学び の流れが自動で回る |
| dogfood | **自分で使ってみる** | 開発者自身が商品を 14 日連続で使って、 本当に動くか確かめる |
| memory consolidation | **記憶の整理** | AI が 「これは大事」 と思って覚えていることが多くなりすぎた時に、 整理して使いやすくする作業 |
| drift detection | **ずれの検出** | 「前と違う方向に進んでる」 を AI が自分で気づく仕組み |
| multi-instance Convergence | **複数 AI の同じ判断率** | 同じ AI が複数いる時、 同じ場面で同じ判断をするか (= AI の一貫性測定) |
| pattern (作業の型) | **作業の型** | 「こういう状況ではこう動く」 を覚えておいて、 似た場面で再利用する仕組み |
| recovery (復旧) | **やり直し** | 何かが壊れた時に、 元の状態に戻して、 もう一度やり直す動き |

### Aira と Yuino の違い

| 専門の言葉 | 普段の言葉 | 何のことか |
|---|---|---|
| Aira (内部実装名) | **内側の名前** | 私たちが自分で使うときの名前。 仕組みの話をするときに使う |
| Yuino (公開 brand 名) | **公開の名前** | あなたが使うときの名前。 商品としての顔 |
| 1 entity 2 narrative | **同じ実体、 2 つの呼び方** | Aira と Yuino は別の道具ではない、 同じ 1 つの道具を、 内側で呼ぶときと、 外で呼ぶときで名前を変えているだけ |
| judgment runtime | **判断の運用エンジン** | 複数 AI を束ねて、 あなたの判断を実行に変える内部の仕組み (技術文書で使う言葉) |
| judgment console | **判断をまとめる画面** | あなたの少ない判断を、 AI 群の実行に変えるための画面 (LP / Gumroad / 商品 UI で使う言葉) |

## 翻訳のルール

このパックの中で「専門の言葉」を「普段の言葉」に翻訳するとき、 4 つのルールに従っています。

### ルール 1: 英語は固有名詞のみ

OK: 「Yuino が会話から気づきを拾う」
NG: 「Yuino が conversation から insight を extract する」

### ルール 2: 比喩を使う

「knot」 → 「結び目」 (糸が結ばれた点 = 大事な箇所が固定された)
「hardness」 → 「硬さ」 (柔らかい結び目はほどける、 硬い結び目はしっかり)
「Discovery」 → 「発見」 (新しい何か)
「Validator」 → 「確認役」 (過去のルールを守る)

### ルール 3: 動詞は和語、 名詞は漢字 + ひらがな

OK: 「気づきの足跡」
NG: 「knot trace」

### ルール 4: 専門用語が必要な時は (= ) で内部用語を併記

OK: 「気づきの結び目 (= knot) は、 AI 研究で 『knot』 と呼ばれている小さな印です」

このルールは公開 docs の最初の 1-2 段落で使い、 以降は普段の言葉のみ使う、 form です。

## 使い方の例

### 例 1: 会話の画面の説明文

技術の言葉:
> "Knot trace shows hardness progression over time"

普段の言葉:
> 「気づきの足跡」 = 過去の気づきがどう積み重なって今の判断になったかの記録です。 硬さ (確信度) が時間とともにどう変わったかが見えます。

### 例 2: setup の説明

技術の言葉:
> "AI agent setup path with prompt template"

普段の言葉:
> AI エージェント (Cursor や Claude Code 等) に 「これを setup して」 と頼むだけで、 自分で操作しなくても準備が完了します。

### 例 3: 全消しボタンの説明

技術の言葉:
> "User can intentionally erase Yuino's memory of conversations, logs, and judgment history"

普段の言葉:
> 「これまでの記憶を全部消したい」 を 1 click でできます。 消した記録だけは残るので、 「いつ消したか」 は後で確認できます。

## 翻訳されない用語 (固有名詞 + 国際用語)

以下の用語は翻訳しないで、 そのまま使います。

- **固有名詞**: Aira / Yuino / nokaze / Zen / Kai / Knot / Claude / Codex / Gemini / Cursor
- **技術の標準語**: API / CLI / Markdown / HTML / Local Web App / SaaS / OAuth / JWT
- **道具の名前**: VitePress / shadcn / Tailwind / Hono / SQLite / lucide-react

## 連絡 + 誤訳の指摘

「この翻訳、 違うと思う」 「もっといい言葉がある」 等の指摘は、 GitHub issue で受け付けています。

このパックは「使いながら良くなる」 構造を持った商品です。 言葉も、 使った人の声で良くなります。
