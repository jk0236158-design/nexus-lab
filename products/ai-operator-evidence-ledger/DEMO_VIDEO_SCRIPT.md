# DevOps×AI Agent Hackathon — デモ動画 ショット構成 + ナレーション草案

> 目的: Devpost/提出用の「動くソリューション」を見せる動画(5分以内必須)。
> 方法: ローカルで evidence-ledger サービスを起動 → ダッシュボード/API を画面収録(or スクショ連番→ffmpeg)+ TTS ナレーション。**Veo 等の高額生成は使わない**(低コスト)。
> 言語: DevOps×AI は日本語イベントなので**ナレーション日本語**、英語字幕は任意で追加可。
> 公開・アップロードはしない(jun レビュー後)。

## 必須要件の充足(動画で見せる点)
- Google Cloud 上で動く(Cloud Run)= デプロイ後の URL or ローカル実機で「動いている」ことを実映像で。
- Google Cloud AI(Gemini)を使用 = claim 分類の enrichment を見せる。
- coding agents(Claude Code / Codex)で作った旨を明示 = 審査加点。
- 「動いている所」を見せる(スライドだけ不可)。

## ショット構成(目安 4:40)
1. 0:00–0:20 フック: 「AIエージェントは『完了しました』と言う。でも、その主張は本物か?」+ タイトル。
2. 0:20–1:00 問題: done 主張と証拠の実体に保証関係がない(報告は自然言語で生成できてしまう)。ダッシュボードの3ケース一覧を映す。
3. 1:00–1:50 happy: 証拠あり → `evidence_backed`。6つの固定チェック(artifact_exists / content_match / test_pass / decision_link / next_action / recency)が通る様子。
4. 1:50–2:40 missing: 証拠なし → `rejected_missing_proof` + repair action 生成(完了をブロック)。
5. 2:40–3:40 stale(肝): `POST /api/recheck {advance_hours:7}` で、初回 green だったケースが `stale_after_recheck` に反転。**「完了は時間で劣化する」= 差別化軸**を実機で見せる。
6. 3:40–4:20 アーキ: Cloud Run + Gemini(claim 分類)+ 決定的な検証エンジン。Claude Code / Codex で実装(加点要件)。
7. 4:20–4:40 締め: completion-truth = 運用の信頼層。synthetic データのみ・境界明示(顧客/売上/本番採用の主張なし)。

## ナレーション草案(日本語・各ショット1–2文)
1. 「AIエージェントに任せると、最後はだいたい『完了しました』で終わります。でも、その文字とコードの実体に、保証はありません。」
2. 「報告は自然言語で生成されるので、状態がどうであれ、それらしい完了文は出せてしまう。だから完了の主張を、そのまま信じない仕組みを置きました。」
3. 「証拠が揃っているケースは evidence-backed。アーティファクトの存在、テスト、決定リンク、次の行動、鮮度——固定のチェックを通って初めて通過します。」
4. 「証拠が無ければ、完了を拒否して修復のタスクを作る。『できました』だけでは止まります。」
5. 「ここが肝です。最初は通っても、時間が経つと、証拠が次の行動から切れていく。再チェックで、それを stale として捕まえます。」
6. 「Cloud Run で動き、Gemini が主張を分類し、検証は決定的なエンジンが担う。実装には Claude Code と Codex を使いました。」
7. 「完了が、ただの言葉に戻らないように。これは運用の信頼層です。デモは合成データで、顧客や売上の主張はしていません。」

## 制作メモ
- 収録は service を `npm start`(鍵ありなら Gemini enrichment も実映像で、無くても fallback で動く)。
- 字幕は後段で確実な日本語フォントを焼く(画面の生成はしない)。
- 提出先 = @nokaze-kaizen に unlisted/private で上げてリンクを Devpost に貼る(公開/アップロードは jun)。
